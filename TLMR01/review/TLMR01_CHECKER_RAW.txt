F-02  MATERIAL  —  ARCHIVE_DECISION_RECONSTRUCTION is a gate that cannot fail.
---------------------------------------------------------------------
WHERE
  TLMR01/code/tlmr01_fixtures.py:78-104  (`reconstruct`)
  TLMR01/out/TLMR01_INSTRUMENTATION_QUALIFICATION.json  ARCHIVE_DECISION_RECONSTRUCTION = "PASS"
  TLMR01/out/TLMR01_MASTER_FREEZE.json  GATES.ARCHIVE_DECISION_RECONSTRUCTION = "PASS"
  the dependence is declared at TLMR01/code/tlmr01_offline.py:8-10:
      "Where a value cannot be recomputed independently -- the component MEMBERSHIP, which the
       archive stores as comp_id -- the archive's own reconstruction gate (§5) is what guarantees
       it"

WHAT IS WRONG
  `reconstruct` builds the "offline" grouping as `groups.setdefault(c,[]).append((y,x))` keyed by
  the stored `c_cid`, which `tl_record` (tlmr01_world.py:68-76) wrote as the index of the online
  component. Regrouping cells by the label the online code assigned them reproduces the online
  grouping identically, for any decomposition whatsoever. The only reachable failure mode is an
  unlabelled cell (`cid.get((y,x),-1)`), which CC.components never produces.

  Demonstrated by replaying the exact comparison logic with deliberately wrong decompositions on
  two well-separated clusters:

      correct decomposition        reconstruct() -> ok = True
      merge everything into one    reconstruct() -> ok = True
      split into singletons        reconstruct() -> ok = True
      scrambled cross-pairing      reconstruct() -> ok = True

  The same tautology appears in tlmr01_paths.py:85-96 (`classify_from_archive`), which also
  rebuilds groups from the stored cid and is described as showing "the archive can name which
  path was taken".

  The consequence is precise: the ONE quantity the offline module declares it cannot recompute
  independently — component membership, which determines the M1 fork event, the M1/M4 occupancy
  stratum, every centroid and every identity link — is delegated to a check that guarantees
  nothing.

CORRECT STATEMENT
  The archive IS sufficient to rebuild component membership (per-cell y,x are stored), but no
  TLMR01 test rebuilds it. Component membership is inherited unverified from
  fdot01_centres.components. The only direct test of that classifier in this mission is the six
  synthetic `components_*` cases in tlmr01_paths.geometry_paths (one centre, two centres,
  toroidal wrap, exactly CORE_R, just beyond, empty).

MITIGATION I ESTABLISHED
  On the two archives available to me, the archive is internally consistent at every one of
  11,000 steps: len(comps) == s.n_components, component ids are contiguous 0..k-1, and
  sum(component nY) == world nY. That is the check `reconstruct` should have been.

F-06  MATERIAL  —  Three categories that cannot take any value but the one
      they took are presented as gates or as empirical results.
---------------------------------------------------------------------
(a) ONLY_Y_LAW_FIELDS_DIFFER
    TLMR01/code/tlmr01_laws.py:44-45
        diffs={k:{"kY":v["kY"],"muY":v["muY"],"p_hop_Y":v["p_hop_Y"]} for k,v in LAWS.items()}
        only_y=all(set(d)<= {"kY","muY","p_hop_Y"} for d in diffs.values())
    `diffs` is constructed with exactly those three keys and then tested for having at most those
    three keys. Tautology. Published as ONLY_Y_LAW_FIELDS_DIFFER: true in
    TLMR01_MEASUREMENT_LAWS.json. It does not check that nothing else differs between the laws.
    The underlying claim is nevertheless TRUE, for a different reason I verified structurally:
    tlmr01_world.build(seed,kY,muY,p_hop_Y,horizon) passes only those into O.build_world; every
    other constant comes from the inherited PQEC01 spec, and build asserts sp.kY/sp.muY/sp.p_hop_Y
    reached the spec (tlmr01_world.py:103-104). NEW_PARAMETER_POINTS = 0 is likewise true by
    construction — every tuple is read from a parent artefact, none is chosen here.

(b) failure_modes.not_exactly_two_centres
    TLMR01/code/tlmr01_offline.py:177 and :194.
    `_candidate_gates` runs only when MATURED (offline.py:165-166), and the candidate step
    cand = i + NEED - 1 satisfies cand <= j because the run length is >= NEED. Every step in
    [i,j] is in the frozen state S, which by state_of requires ncen == 2. Therefore
    GATE_exactly_two_centres is true by construction for every matured episode, and the mode can
    never fire. Observed: 0 / 0 / 0.
    TLMR01_FINAL_REPORT.md §6 prints a column "failed on centre count" of 0, 0, 0. That is an
    identity, not a measurement. (Strictly, it is a weak archive-self-consistency check, since
    state_of reads the `s` array's n_components while the gate reads the `k` rows.)

(c) Episode terminators INTEGRITY_FAULT and UNCLASSIFIED
    TLMR01/code/tlmr01_offline.py:60-67 and :149-153.
    `state_of` takes a per-WORLD integrity flag. If it is False every step is "F", so no run of
    "S" exists and no episode can terminate in "F". If it is True no step is ever "F". So
    INTEGRITY_FAULT is unreachable either way. And st[j+1] can never be "S" because j is maximal,
    so the `.get(nx,"UNCLASSIFIED")` default never fires. Observed across 16,943 episodes:
    INTEGRITY_FAULT 0, UNCLASSIFIED 0.
    Y_EXTINCT is genuinely reachable but observed 0 times, while extinction itself is common:
    the steps that are neither single-centre nor inside an S episode (extinct, or three-or-more
    centres) have per-world median 4,498 at LAW_A, 724 at LAW_B and 1,918 at LAW_C, and one of
    the two cross-check worlds is extinct for 8,202 of its 11,000 steps. Extinction is nowhere
    reported.

# HANDOFF — FTCTR01 EXECUTABLE BYTE RECOVERY 01

**Conditional.** This is the *only* successor authorised by FTCTR01's `STOP__CRITICAL_EXECUTABLE_BYTES_MISSING`.
It is **not** a scientific mission. It runs **zero** engine starts, creates **zero** worlds, consumes
**zero** seeds. It has exactly one job: decide, by bytes, whether the two-centre Y/X architecture
exists **anywhere**, and if so bind it.

---

## Trigger condition

Run this **only if** at least one of the following is true:

* Tommy states that the Y/X two-centre developmental code lives in a repository, folder, machine,
  archive or cloud location **other than** `C:\Users\tommy\Documents\ising v3`; **or**
* a location is identified that was never reachable from a Cowork session (another device, an
  external drive, a private remote, a chat attachment, a `.bundle` held outside the repository).

If neither is true, **do not run this handoff**. In that case the correct next action is not a
recovery mission at all — see "If nothing is found" below.

## Method

1. Enumerate candidate locations **before** searching any of them; write the list down first.
2. For each location, run the FTCTR01 byte-binding protocol verbatim
   (`FTCTR01_BYTE_BINDING_CERTIFICATE.md` §2), including the positive control at every stage. A
   search without a positive control is not evidence of absence.
3. Cover unreachable objects, bundles and archives explicitly, as implementation 2 did — the
   FTCTR01 check found one orphan history invisible to `git grep`.
4. Publish `FTCTR02_PARENT_BINDING.json` with the same field structure, so the two are comparable.
5. Terminal dispositions: `EXECUTABLE_BYTES_RECOVERED__FTCTR01_MAY_RESUME` (list every bound object
   with its coordinates) or `STOP__CRITICAL_EXECUTABLE_BYTES_MISSING__ALL_LOCATIONS_EXHAUSTED`
   (list every location searched, with its positive control).

If **1–9** bind, FTCTR01 resumes **from its §2 freeze**, unmodified — the freeze must still be
written before any timing array is opened.

## If nothing is found

Then the honest conclusion is that the two-centre Y/X programme was **never executed as code**, and
every quantity attached to it — `TAU_SEP = 125`, the `101 births / 250 steps` function threshold, the
`C3` third-centre surrogate, the observed separation and hold times — is **conversational, not
executable**. In that case:

* do **not** open a recovery mission a second time;
* mark those quantities `NON_EXECUTABLE__WITHDRAWN` wherever they are cited;
* the next scientific action is chosen from the substrates that **do** survive by bytes
  (`edlab/substrates/*`, the `lattice_bond` individuation line, the `AXMAT00` / `FCDDH01R` /
  `FCDDH00` chain), not from this vocabulary.

That is a real result: it removes a phantom clock from the programme's critical path.
